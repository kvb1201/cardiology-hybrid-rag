## 2. Prompt Version & Templates

**Prompt Version:** `v1.0` (FROZEN)

### System Prompt (`v1.0`)
```text
You are an impartial automated evaluator assessing the quality of answers generated by a retrieval-augmented generation (RAG) system in cardiovascular medicine.

You must evaluate the Generated Answer against the Reference Evidence and the Clinical Query along exactly three dimensions:
1. evidence_coverage (0.0 to 1.0): How completely the generated answer addresses the key facts and clinical information supported by the provided reference evidence that are relevant to answering the query.
2. factual_consistency (0.0 to 1.0): Whether claims in the generated answer are supported by the provided reference evidence, without unsupported additions, contradictions, or fabricated facts (penalize ungrounded statements or hallucinations).
3. answer_relevance (0.0 to 1.0): How directly, appropriately, and completely the generated answer addresses the clinical query using the available evidence.

Important Guidelines:
- Reason strictly and solely from the provided Reference Evidence and Clinical Query.
- Do not use external medical knowledge to verify claims beyond the provided evidence.
- You are evaluating automated answer quality relative to the provided evidence, NOT general clinical correctness or clinical advice validity.
- Do not attempt to judge or speculate about the retrieval system or generator model.
- Assign numeric scores between 0.0 and 1.0 for each dimension.
- Provide a concise rationale for each score explaining your assessment.
- Respond strictly with a valid JSON object matching the required schema.
```

### User Prompt Template (`v1.0`)
```text
### Clinical Query:
{query_text}

### Reference Evidence:
{reference_evidence_text}

### Generated Answer:
{generated_answer_text}

Evaluate the generated answer based strictly on the reference evidence and clinical query. Output valid JSON matching the schema.
```

| **Experimental Condition Key** | **NO** | Condition identifiers `(query_id, retriever, k)` are handled purely at the pipeline level. |

## 4. Evaluation Dimensions & Scoring Scale

Evaluation is conducted on a continuous fixed numeric scale from **0.0 to 1.0**:

1. **Evidence Coverage ($0.0 - 1.0$):**
   * *Definition:* How completely the generated answer addresses the key facts and clinical information supported by the provided reference evidence that are relevant to answering the query.
2. **Factual Consistency ($0.0 - 1.0$):**
   * *Definition:* Whether claims in the generated answer are supported by the provided reference evidence, without unsupported additions, contradictions, or fabricated facts. Hallucination detection is incorporated here by penalizing ungrounded statements.
3. **Answer Relevance ($0.0 - 1.0$):**
   * *Definition:* How directly and appropriately the generated answer addresses the clinical query using the available evidence.

---

## 5. Programmatic Composite Quality Calculation

To guarantee mathematical integrity, the composite quality score is **never entrusted to LLM arithmetic**. It is calculated programmatically in Python after response validation:

$$\text{composite\_quality} = \frac{\text{evidence\_coverage} + \text{factual\_consistency} + \text{answer\_relevance}}{3.0}$$

The score is rounded to 4 decimal places. Python unit tests verify that any model-generated composite value is ignored in favor of the programmatic arithmetic mean.

## 6. Structured JSON Schema & Cohere Enforcement

Output structure is strictly enforced via Cohere Chat API v2 `response_format`:

```json
{
  "type": "json_object",
  "schema": {
    "type": "object",
    "properties": {
      "evidence_coverage": {"type": "number"},
      "factual_consistency": {"type": "number"},
      "answer_relevance": {"type": "number"},
      "rationales": {
        "type": "object",
        "properties": {
          "evidence_coverage": {"type": "string"},
          "factual_consistency": {"type": "string"},
          "answer_relevance": {"type": "string"}
        },
        "required": ["evidence_coverage", "factual_consistency", "answer_relevance"]
      }
    },
    "required": ["evidence_coverage", "factual_consistency", "answer_relevance", "rationales"]
  }
}
```

Python validation ensures:
- All three dimensions exist and are floats/ints in $[0.0, 1.0]$.
- All three rationales exist as non-empty strings.
- Absence of markdown backticks or fences.

## 8. Retry Policy & Rate Limiting

- **Concurrency:** `1` (serial execution to respect the 20 RPM trial tier ceiling)
- **Inter-Request Delay:** `3.5s` (guarantees $\le 15$ RPM throughput)
- **Timeout:** `60s` per request
- **Retry Strategy:** Bounded exponential backoff (initial delay: 3.0s, factor: 2.0, max: 15.0s, max retries: 3)
- **Quota Guard:** Explicitly detects HTTP 429 monthly quota exhaustion and terminates with `MonthlyQuotaExceededError` instead of burning retries.

- **Unique Condition Key:** `(query_id, retriever, k)`
- **Output Format:** JSON Lines (`.jsonl`)
- **Resumption Logic:** Reads all existing records with `status: "success"` in the target output file before starting. Already completed conditions are skipped immediately with zero API calls.

## 10. Critical Reference-Evidence Dependency Caveat

> [!WARNING]
> **Methodological Caveat on Reference Evidence:**  
> The reference evidence used by the downstream evaluator is derived from the study's grade-2 qrels annotations. It is **NOT** independent clinician-authored ground truth. Consequently, automated answer quality scores share an underlying reference dependency with conventional retrieval metrics. This evaluation assesses **automated downstream answer quality relative to retrieved/qrels evidence**, NOT absolute clinical safety or external clinical correctness.

### Qualitative Discernment Observations
1. **Clinical Sensitivity Under Poor Retrieval:** In Condition 7 (`Q027` with LSH at $K=5$), LSH failed to retrieve relevant evidence on atrial fibrillation risk factors. The generated answer stated that the passages did not contain risk factor information. The evaluator correctly scored Evidence Coverage at `0.00` and Relevance at `0.00`, but gave Factual Consistency `1.00` because the model truthfully acknowledged the evidence gap without hallucinating. This produces a composite score of `0.3333`, confirming that downstream evaluation accurately tracks retrieval failure.
2. **Discriminating Nuance in Guideline Adherence:** In Condition 4 (`Q009` with BM25+Dense RRF at $K=10$), the evaluator correctly noted in its rationale that the generated answer cited the FLOWER-MI trial which was not present in the reference passages, and flagged a minor numeric discrepancy regarding FFR hemodynamic thresholds (0.75 vs 0.80).

## 12. Known Limitations & Production Readiness

1. **Trial Key Monthly Cap (1,000 Calls):** The Cohere Trial key has an aggregate ceiling of 1,000 calls per calendar month.
   - For the **885 primary grade-2 conditions**, the workload fits comfortably within the 1,000 call limit.
   - For all **975 conditions**, the margin is tight; upgrading to a pay-as-you-go key ($0.54 USD total) completely eliminates quota constraints.
2. **Read Timeout Resilience:** On very long input prompts (e.g., $Q009$ with ~18k characters of reference evidence), Cohere response latency occasionally exceeds 60 seconds. The evaluator's automatic retry policy successfully handled this with zero data loss.
3. **Execution Readiness:** The evaluator architecture, schema validation, test suite, and pilot validation are complete and ready for execution upon user authorization.
